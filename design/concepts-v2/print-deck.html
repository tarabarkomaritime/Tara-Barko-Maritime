Concept A

Manifest

The catalogue that ships today, made findable. The three-table layout is kept exactly as built — what changes is everything around it.

Desktop · 1224px
Phone · 390px

What changes

  • Search moves into the hero — the first thing on the page
  • Day and mode filter chips above the table
  • Head row stays pinned while you scroll
  • Rows are clickable and reveal Enroll →

What stays

  • Three side-by-side tables, rows locked together
  • 15 courses a page, 15 pages
  • Days centred, mode centred
  • “Other courses may be available” footer
Build cost: lowest. Mostly CSS, plus two filter handlers over the catalogue that already exists. Nothing about the data or the enrollment flow changes.

Concept B

Deck Cards

The table becomes a card grid, grouped by how long each course takes — because “what can I finish before I join?” is the question between contracts.

Desktop · 1224px
Phone · 390px

What changes

  • One course per card: title, days, mode, Enroll
  • Grouped by length — one day, two days, six and longer
  • Popular course shortcuts under the search box
  • Paging replaced by “show all 64 one-day courses”

Trade-offs

  • Best of the three on a phone
  • Fewer courses visible at once on a desktop
  • Catalogue stops being a scannable reference table
  • Largest rewrite of the three
Build cost: highest. New render function and grouping logic. Worth it if the catalogue is meant to sell courses rather than list them.

Concept C

Ship’s Index

No paging at all. All 222 courses on one page, grouped A–Z, with a letter rail and a filter box that narrows the list as you type.

Desktop · 1224px
Phone · 390px

What changes

  • Every course on one page, grouped A–Z
  • Letter rail down the side; headings pin as you scroll
  • Type to filter — the list narrows instantly
  • Ctrl+F finds anything; nothing hides on page 9

Why it suits this business

  • The whole list can be screenshotted and sent on Messenger
  • Applicants usually arrive knowing the course name already
  • Deletes the pager and its page-window logic
  • Cost: one long page instead of fifteen short ones
Build cost: low — it removes code. The pager, the page clamping and the ellipsis windowing all go away and are replaced by one filter.

Recommendation. Ship Concept A and take Concept C’s filter-as-you-type with it. A is the smallest change to code that already works, and the filter chips fix the real problem: nobody pages through fifteen screens to find a course they were told to take by name. Keep Concept B in reserve — it is the better shop window if the catalogue is ever meant to sell courses rather than list them.
One open question before any of this ships. The Mode of Training column now reads “Face to face” for every course the price matrix does not describe. That is the house default you confirmed, and it is on 76 of the 222 listings. If any of those are in fact delivered blended or by distance learning, the catalogue is telling applicants the wrong thing — worth one pass through the list before it goes public.
