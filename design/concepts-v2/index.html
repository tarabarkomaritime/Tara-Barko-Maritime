Course catalogue — three directions

Same 222 courses, same data, three ways of putting them in front of a seafarer. Each one is a real page: open it, resize it, click around.

CONCEPT A

Manifest

What ships today, made findable.

What changes

  • Search moves into the hero — it is the first thing on the page
  • Day and mode filter chips above the table
  • Head row stays pinned while you scroll
  • Rows are clickable and reveal Enroll →
  • Three-table layout kept exactly as built
Cost: a few hours. Mostly CSS plus two filter handlers over the catalogue you already have.
Open Concept A
CONCEPT B

Deck Cards

Browse by how many days it takes.

What changes

  • Table becomes a card grid — one course per card
  • Grouped by length: one day, two days, six and longer
  • Every card carries its own Enroll button
  • Popular course shortcuts under the search box
  • Paging replaced by “show all 64 one-day courses”
Cost: a day or so. New render function, new grouping, and the catalogue stops being a reference table.
Open Concept B
CONCEPT C

Ship’s Index

All 222 on one page. No paging at all.

What changes

  • Every course on one page, grouped A–Z
  • Letter rail down the side; letter headings pin as you scroll
  • Type to filter — the list narrows instantly
  • Ctrl+F finds anything; nothing hides on page 9
  • Compact rows, Enroll on each one
Cost: half a day. Simpler than what exists — the pager and its page-window logic get deleted.
Open Concept C
If you want one recommendation: ship Concept A now and take Concept C’s filter-as-you-type with it. A is the smallest change to what is already built and working, and the filter chips fix the real problem — nobody pages through fifteen screens to find a course they were told to take by name. Concept B is the better shop window if the catalogue is ever going to sell courses rather than list them.
